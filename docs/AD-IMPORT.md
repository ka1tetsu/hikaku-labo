# 楽天トラベル広告HTMLの自動登録

楽天アフィリエイトで取得した1施設分の「画像＋テキスト」素材をファイルに保存して実行します。管理画面のパスワード・APIキーは不要です。

```sh
export PATH=/workspace/.cloud-tools/node_modules/.bin:$PATH
cd /workspace/hikaku-labo
npm run ads:import -- --file /tmp/広告素材.html
```

標準入力でも登録できます（素材を貼り付け、最後に改行して Ctrl+D）。

```sh
npm run ads:import
```

施設名・施設番号・紹介IDを読み取り、施設名に含まれる都市名から掲載エリアを設定します。今回提供された「ホテル法華クラブ函館」は `hakodate` と自動判定して登録済みです。確認箇所は `/travel/?destination=hakodate#booking` の「ホテル・宿」欄です。

施設名だけでは所在地を確定できないため、出力された `destinationId` を確認してください。都市を判定できない場合は登録せず停止します。所在地を確認したうえで `--destination hakodate` のように都市IDを指定できます。

原文HTMLは `src/travel/ads/<ID>.html` に変更せず保存し、一覧は `src/travel/ads/index.json` に自動登録します。React側は一覧を読み込み、該当エリアで1泊以上の宿泊検索時だけPR表示とともに掲載します。広告の追加ごとにコンポーネントを編集する必要はありません。既存の一般検索用の紹介IDや比較順位は変更しません。

同じ素材の再登録では重複しません。同一施設の別素材への差し替えには `--replace` が必要です。スクリプト、イベント属性、外部ホストのリンク・画像、異なる施設へのリンク、未対応のタグ・スタイルは登録しません。汎用バナー・A8・商品広告は今回のインポーターの対象外です。

画像と施設名の自然なクリックを既存の `/api/track` に記録し、`merchant: rakuten-travel`、`placement: rakuten-hotel-126` のように施設別に集計できます。広告リンク・計測画像への自動アクセスは行いません。`VITE_RAKUTEN_TRAVEL_DISABLED=true` で非表示にできます。

登録後は `npm run test:all`、`npm run lint`、`npm run build`、`npm run verify:build` を実行し、通常のサイト公開手順で反映します。自動登録はファイル設定までです。ASPの提携申請・媒体登録の確認・本番公開・予約・売上発生を自動化するものではありません。掲載を認められたサイトで使用してください。

## 複数施設の一括取込

```sh
npm run ads:import -- --directory /tmp/楽天トラベル広告素材
```

サブフォルダ内も含む全 `.html` / `.htm` を読み込みます。1ファイルに1施設分の原文素材を保存してください。全素材を検査してから登録するため、不明な都市・不正な素材・同一施設の競合があれば既存一覧を更新せず停止します。同じ素材は重複登録しません。ファイル書込み自体のI/O障害時はエラーを確認してください。

## 宿の横並び比較

`/travel/` で旅行先を選び、「ホテル・宿」の登録済み宿から名前で絞り込み、「比較に追加」を選択します。最大4施設を横並びにし、同じ日程・泊数・人数・室数で確認した全員・全泊分の支払総額を入力できます。1人あたり・1室1泊あたりを計算し、部屋・食事・キャンセル条件をメモできます。旅程条件が変わると、古い金額を使わないよう選択と入力をリセットします。入力内容のサーバー送信・永続保存はしません。

これは手入力の比較機能です。価格・空室をAPIで取得する機能ではありません。広告リンクにも旅程条件は付加しません。全施設分のデータが未接続の現在、登録は提供済みのホテル法華クラブ函館1施設のみです。

## 楽天トラベル掲載全施設の登録に必要な設定

全施設の登録と、提供HTML素材の一括取込は異なります。全施設の公式一覧・所在地・更新／削除情報を取得するには、利用可能な楽天トラベルAPIまたは正規データの提供が必要です。現在、全件同期処理は未実装で、全施設登録も未完了です。

2026-10-27時点で、この環境への `RAKUTEN_ACCESS_KEY` と `RAKUTEN_APP_ID` の注入は未設定です。公式ドキュメントとAPIへの通信許可は反映され、仕様を参照できることを確認しました。利用者が使用を指定した接続情報で、現行APIに `hotelNo=126` と vivlica.com のOrigin/Refererを指定したところ、HTTP 403（`HTTP_REFERRER_NOT_ALLOWED`）で拒否されました。キーの値はファイル・Git・公開JavaScriptに保存していません。

対象アプリの許可サイト設定に `https://vivlica.com/` を登録し、そのアプリの値を環境設定と本番ホスティングのサーバー用環境変数に設定する必要があります。APIキーは `VITE_` 変数へ入れないでください。現在のVercelへのデプロイはGitHubのmain連携で行います。クラウド環境の設定保存・Publishと、Vercelの本番環境変数設定は別の操作です。

環境設定のドラフトには、通信許可 `webservice.rakuten.co.jp` / `openapi.rakuten.co.jp`、シークレット要件 `RAKUTEN_ACCESS_KEY`（送信先 `openapi.rakuten.co.jp`）、環境変数要件 `RAKUTEN_APP_ID` を登録済みです。既存の許可先は保持しています。

現行仕様で確認した取得方法：

- 地域階層：`Travel/GetAreaClass/20140210`。子区分があれば細区分まで列挙します。
- 施設取得：`Travel/SimpleHotelSearch/20260731`。各末端地域コードを指定し、1ページ30施設・最大100ページを走査します。
- 取得総数（recordCount）と取得済みのユニーク施設番号を照合し、100ページ上限を超える地域や失敗した地域を未完了として扱う必要があります。
- `hotelMinCharge` は1部屋1泊あたりの最安値の目安です。日付・人数を指定した予約総額とは区別します。
- 紹介URLはAPIが返す正式なURLを利用します。既存広告素材の施設番号を書き換えて全施設分の素材を作りません。

サイト登録制限の解消と実接続を確認してから全件同期処理を実装・実行する必要があります。API取得範囲が楽天トラベル全掲載施設を網羅するとは、検証するまで断定しません。予約APIの正常応答・全施設登録・空室の自動比較は未達です。
