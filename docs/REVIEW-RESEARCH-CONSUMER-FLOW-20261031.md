# Vivlica 消費者の購入・口コミ調査導線監査 — 2026-10-31

## 優先的に修正した障害

1. **口コミが出品行の片隅に埋もれていた**：商品ごとのレビュー一覧を独立した「口コミ・星評価から購入先を調べる」調査セクションとして比較結果上部に配置した。取得済み候補数、商品レビュー有無、店舗レビュー有無、評価未取得件数を明記。
2. **消費者が評価の多い商品を絞れない**：元の「星評価」の最小値に加え、商品レビュー件数10/20/50/100以上と、店舗★4.0/4.5以上を**個別フィルタ**として追加。「★4.0以上・20件以上」「★4.5以上・50件以上」のワンタップ絞り込みも追加。
3. **星5.0・1件が星4.5・多数件より上に見える**：既存の信頼度補正値（事前平均3.8、擬似件数15）を継続し、レビュー研究パネルもこれで並べる。特に20件未満は件数が少ない注意表示。数式は品質保証・サクラ検出ではない。
4. **商品レビューとショップ評価を混同する**：Yahoo!の `hits[].review.rate/count/url` と `hits[].seller.review.rate/count` を独立した列に分離。販売店スコアの有無が商品スコアを上書きしない。双方の評価母集団を横断して平均しない。
5. **他サイトのレビュー本文をコピーしていたかのように見える**：Yahoo公式のレビューページURLがHTTPSかつ `shopping.yahoo.co.jp/review/` の場合だけ原文へリンク。楽天はレビューページURLを勝手に生成せず、商品販売ページで確認を促す。Amazonは公式検索へのリンクのみ、星評価やレビュー本文は無許諾転載しない。
6. **検索語が広いと異なる製品の星数を混ぜる**：JAN/型番の照合がある場合はそれらの口コミ候補に限定。ない場合は「商品名が似た出品・同一商品未確認」と明記。色・容量・付属品は別途確認。
7. **評価フィルタが厳しすぎて0件になると行き止まり**：失敗理由を「口コミ未取得の商品も対象外になる」と説明し、検索条件をワンタップ解除して復帰。新しい検索へ移動した場合は口コミフィルタも初期化。
8. **広告と商品の順位の混同**：購入・Amazonへの送客リンクは設定済みの広告・PR表記を維持。公式サイトへの口コミ原文リンクはアフィリエイト広告扱いしない。商品レビューの研究結果と広告報酬を無関係に保つ。

## データの出典と利用許諾

- Yahoo!ショッピング [商品検索API v3](https://developer.yahoo.co.jp/webapi/shopping/v3/itemsearch.html)：2026年7月31日に `hits/review/url` と `hits/seller/url` の説明追記。商品評価の平均・件数・口コミURL、店舗レビューの平均・件数、JAN/商品状態/在庫は公式APIに記載されている。既存接続クライアントIDを使用。利用約款とレート制限（同一URLへの頻繁なアクセスを控える）を遵守。
- 楽天 [商品検索API](https://webservice.rakuten.co.jp/documentation/ichiba-item-search)：`reviewAverage` と `reviewCount` の集計が取得できる場合のみ表示。楽天HTTP403が継続しているため、正常取得したと断定しない。
- Amazon [アソシエイト・プログラム参加要件](https://affiliate.amazon.co.jp/help/operating/policies)：カスタマーレビューやstar ratingの表示・使用は原則禁止。Creators APIのレビュー・評価リンクを正規に取得してライセンス条件を遵守する場合だけ例外。現状はCreators API未接続で、Amazonの星数・口コミ本文を転載・集計しない。

## メトリクスの解釈に関する注意

- **商品口コミの平均点はサイト/出品ごとの観測値**。異なるJAN・容量の評価や販売店の接客評価の混合を避ける。
- 未取得の星評価はゼロスターではなく「未取得」。特定店舗を否定的に評価したと推測しない。
- 口コミを選択するフィルタは「このページで公式APIから取得済みの出品」に限定。ユーザーが外部リンクで見つけたレビューを無断コピーしない。
- 販売価格・送料・ポイント・レビューは取得時点の表示であり、最終購入で仕様・返品・配送条件を確認する。
- ユーザー別の閲覧履歴、名前、住所、レビュー本文、キーワードを保存する分析イベントを新設しない。既存の匿名クリック経路を尊重。
- 「同じ出品における商品レビュー数」を加算して**全ECモールの口コミ数**に見せない。各サイトの別々のデータを合計するのは不適切。

## 計測と今後のAPI拡張

- `product_search`→`product_results_ready`→`product_offer_selected`→購入先リンクのCTR、レビューへのリンクのクリックは混同せずに見る。実際の売上はASPの確定成果でのみ判断。
- Yahoo!の公式評価データを継続利用し、楽天403の認証問題、Amazon Creators APIの資格・レビュー取得制限を別途解消する。第三者サイトのレビューを規約に反してスクレイピングしない。
- A/Bテストでは「レビューを見る→最安候補へ進む」導線と「先に価格を見る」導線を比較し、実際の送客と購入成立率を測る。統計的に裏付けがない見せかけの★評価・偽投稿・架空口コミを表示しない。
