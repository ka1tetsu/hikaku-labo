# 比較ラボを価格.com型の購入判断サービスへ近づける改善一覧

2026-11-03。価格.comの公式利用ガイドと比較ラボの現行コードを照合した。価格.comのブランド・画面素材・レビュー・商品DBを転載する計画ではない。優先順位は現行機能とデータ制約からの判断であり、売上やCVRの改善効果を測定したものではない。

## 目指す流れ

カテゴリや用途で製品を探す → 同一仕様の製品を特定する → 販売店ごとの実際の購入条件を比較する → 口コミ・仕様・推移を確認する → 候補を比較・保存する → 販売店へ進む。

価格.comの製品ページは販売店の価格一覧から購入先へ進め、仕様・レビュー・クチコミを別のタブで確認できる。価格推移は最長2年。複数製品の比較や、お気に入り・希望価格の通知も提供する。現在の比較ラボの問題は、出品の価格と参考指数などの分析パネルが同じ長いページに積み重なり、基本の購入判断が後回しになること。

## 改善と不足（P0を先に実施）

| 優先 | 改善点 | 現状・今回の対応 | 完成に必要なもの／確認方法 |
|---|---|---|---|
| P0 | 価格と購入先を先に表示 | 今回、型番・JAN検索の標準を販売店別価格表へ変更。口コミ・参考指数は開閉式に整理 | スマホの価格確認・販売店クリック・比較追加の完了率を別々に見る |
| P0 | 製品と出品を分離 | 型番/JANの一致・類似判定は既存機能。カテゴリ検索に別製品が混ざり、単一製品DBはない | 製品ID→仕様違いSKU→出品の三層データモデル。型番文字列だけで同一商品を断定しない |
| P0 | 色・容量・世代・セット違いの識別 | JAN再検索を価格表にも設置。型番一致では仕様を別途確認する表示 | メーカー等の許諾済み仕様データ、GTIN/JAN整合、誤マッチ除外テスト |
| P0 | APIの取得成功率 | Yahoo/楽天の状態表示と失敗時の他店確認は既存。登録・資格・割当条件の復旧はUI変更だけでは不可 | 取得成功率、取得時刻、タイムアウト、欠測率をAPI別に監視。未取得を0円にしない |
| P0 | 本当に払う総額 | 送料無料確認額と手入力の送料・クーポン計算は既存。価格表でも送料・在庫を同じ行へ | 配送先、条件付き送料、クーポン資格、決済条件。未知の送料を無料と推定しない |
| P0 | スマホでの比較継続 | 今回、最大4件の選択トレイと、価格表／詳しい出品一覧の切り替えを追加 | 選択が表示切り替えで失われないこと、画面全体が横にはみ出さないことを検証 |
| P1 | カテゴリ別スペック検索 | ホームのカテゴリとキーワード・価格・評価絞り込みは既存。重量、寸法、対応規格などの横断仕様検索はない | カテゴリ別属性スキーマ、メーカーの出典、単位正規化、不明値の扱い |
| P1 | 製品固有の詳細ページ | 比較URLはあるが、安定した製品ID・SKU別ページの基盤がない | 恒久URL、仕様・出品・出典の更新、重複canonical管理。文字列検索URLの大量生成で代用しない |
| P1 | 独立した仕様比較 | 現在の比較表は出品条件の比較。製品の性能比較ではない | 同一単位の仕様DBと比較項目。高価格やレビュー件数を性能とみなさない |
| P1 | 価格推移 | 現状は観測履歴DBなし。架空のグラフは作らない | API契約の保存条件を確認し、取得日時・送料条件・欠測を持つ観測DBを構築。継続収集後に提供 |
| P1 | お気に入り・再訪 | 目標価格と検索条件を端末に保存する既存機能あり。販売店データは保存しない | 製品ID基盤とAPI許諾に沿った再取得。端末保存とアカウント同期を明確に分ける |
| P1 | 希望価格の通知 | 現状はページを開いた際の目標価格確認。無人のメール・プッシュ監視ではない | サーバー定期処理、本人同意、通知先認証、解除・重複抑止・費用上限。通知機能があると偽らない |
| P1 | 口コミの質と店舗の信頼性 | 商品評価・販売店評価を分離し、件数を考慮する参考指数あり。価格表でも分離表示 | 原文・取得元・件数・時刻を維持。異なるサイトの星の平均を自動合算しない |
| P1 | 店舗の条件比較 | 送料・在庫・状態は取得値で表示。納期・延長保証・返品条件は網羅していない | 店舗の公式規約と更新日、API対応項目。配送地域や保証条件を推定しない |
| P2 | 人気ランキング | 一般検索は取得元の関連度。独自の売上・人気を確認できるデータなし | 集計母数・期間・対象を示す実測データ。クリックランキングと販売ランキングを区別 |
| P2 | 自社レビュー／クチコミ | 投稿・認証・運営体制なし。他社投稿の転載は行わない | 投稿同意、利用規約、審査・通報・削除、なりすまし・広告投稿対策。実利用のない体験談を作らない |
| 横断 | 収益と比較の中立性 | アフィリエイト開示、報酬を順位に使わない方針、自動QA通信の除外は既存 | 取得→比較→出品選択→販売店クリック→ASP成果→確定→直接費控除を別指標として評価 |

## 今回の公開範囲

- 販売店ごとの価格・送料・在庫・商品評価・店舗評価・購入先を一つの表へ。モバイルでは表を画面幅内の行として読みやすく表示する。
- ホームの横並び比較の購入先を修正。Yahoo!ショッピングの出品を楽天市場へ取り違えず、元のURL・広告区分を維持する。送料不明・ポイント参考額の表現も修正。
- 型番/JANでは価格表が標準。一般キーワードは関連度による出品一覧が標準で、表示形式は切り替え可能。価格とポイント考慮後の参考額は混同しない。
- 詳細フィルター、口コミ調査、参考指数は開閉式。既存の機能・導線・出典・広告表示を維持する。
- 比較候補は最大4件。画面下から比較表へ移動できる。出品条件を比較する機能であり、許諾済み仕様DBや価格履歴・通知の実装とは区別する。

## 実装順

1. 購入判断の基本動線と価格表を整える（今回）。
2. API接続と欠測・誤マッチの計測を安定させる。
3. 需要のある少数カテゴリから、出典付き製品ID・SKU・属性DBを作る。
4. 複数製品の仕様比較、製品詳細、再訪を一貫させる。
5. データ保存条件・運用費・通知同意が整った段階で、観測履歴と通知を提供する。
