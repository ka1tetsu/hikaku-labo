# Vivlica 収益改善の最優先手順 — 2026-10-29

この文書は **A8.net・楽天・Vercel・Search Console の実データを自動取得したレポートではありません**。GitHubの公開コードと、確認済みのユーザー提供素材を監査した運用アクションです。広告をクリックした回数と「発生成果」「確定報酬」「利益」は別の指標です。

## 現状とブロッカー

| 項目 | コード上で確認できる事実 | 利益への影響 |
|---|---|---|
| 正規ドメイン | `src/shared/site.js` は `https://vivlica.com` | 旧Vercelドメインからリダイレクトする想定。DNS/TLS/本番ドメインの実画面は別途要検証 |
| A8.net Yahoo!トラベル | ユーザー提供の原文広告素材2件は保存済み。ただし、新ドメインと同じ `VITE_A8_TRAVEL_REGISTERED_ORIGIN` がない限り非表示 | 新ドメインのA8.net登録・Yahoo!トラベルの提携確認が必要 |
| 通信・カード・保険・ITサービス | 環境変数 `VITE_AFF_URL_<ID>`、`VITE_AFFILIATE_LINKS` で広告を掲載する仕組み。リポジトリ内のA8ツール素材は未設定 | 成果が発生する広告主・案件の承認と正式な素材の追加が必要 |
| 航空券・ホテル | 各社への検索導線があり、対応する出発地と日付を引き継げるサイトを増やした | Trip.com/Booking.com/Skyscanner等の実IDが無ければ多くが公式リンク |
| 楽天関連 | 既存の公開アフィリエイトIDを用いた紹介リンクあり | IDの所有、有効性、許可サイトに `vivlica.com` が含まれるかは要確認 |
| 検索流入 | 主要ページのsitemap、robots、事前描画・構造化データを実装 | Search Consoleの所有権・インデックス・表示回数・CTRは未取得 |
| 収益 | `npm run report:revenue` によるクリック/閲覧と利益集計に対応 | ASPの確定報酬・Vercel/ドメイン/APIの請求額を入れなければ利益は不明 |
| 外部アクセス | GitHub側のVercelデプロイ成功を確認したが、Vercel管理APIは403。外部ブラウザからVivlicaの画面が取得できない | 公開URL・DNS・リダイレクト・監視の実測をVercelで確認する |

## 最初の3つの運営者作業（高優先度）

1. **A8.netのサイト情報**で現在の正規URL `https://vivlica.com/` を登録し、Yahoo!トラベルのプログラムが登録したメディアとこの公開サイトで有効か確認。既存 `https://hikaku-labo.vercel.app/` の登録だけでは足りない。Yahoo!トラベルの「広告掲載URL管理」には、少なくとも `https://vivlica.com/travel/` を提出。必要であれば同プログラム内の別の広告掲載ページも申告。確認後だけVercel Productionの公開設定 `VITE_A8_TRAVEL_REGISTERED_ORIGIN=https://vivlica.com` を設定し再ビルド。**勝手にA8コードからクリックURLだけ抜き出さない**。
2. **広告主提携を優先順に**：まず高意図の通信・光回線、ITサービス、楽天トラベル、Trip.com/航空券、eSIM。提携中のサービスID/環境変数名は `npm run audit:affiliate`、現在ドメインの不足項目は `npm run audit:activation` で確認。ユーザーがASPから発行された正規素材だけを設定。高い推定報酬でランキングを操作しない。
3. **利益の証明**：A8.net・楽天・旅行系ASPそれぞれの「確定報酬（同一期間）」を取得し、Vercel・ドメイン・AI/APIの実請求額を取得。同じ期間で `npm run report:revenue` を使って利益算出。表示数・クリック数・発生成果数は確定利益ではない。

## 今回のコード改善

- 海外などの出発地を明示しない場合や出発日がない場合、航空券検索リンクへ**勝手に東京出発・架空の日付を代入しない**。条件を引き継げる検索サービスだけ実行可能な検索URLを提示し、未対応サービスは公式サイトに戻す。
- 航空券の各社トップページへの単純な遷移の一部を、既存の `buildFlightLinks` で日付・出発都市・人数が入る検索導線に置換（有効なアフィリエイト設定がある場合のみ広告として記録）。
- CIに **非ブロッキングな** 収益化チェックリストを追加。Vercelの本番環境変数はGitHub CIから通常見えないため、CIの未設定表示を本番の未設定と断定しない。
- 商品紹介・A8.net原文広告コード・クリック計測の仕様は変更しない。

## ここからの計測サイクル

毎週、① Search Consoleの検索表示数・流入 ②ページ別の閲覧（ボット/再訪も含む）③外部送客クリック（PR・通常）④ASPでの確定報酬 ⑤請求額を同じ期間で確認する。広告施策を追加するのは、**新規広告費をかけても黒字になる数字**が分かってから。機械的に大量の記事を追加すると、質が不十分で検索流入の足を引っ張るリスクがあるため、一次情報と利用者体験を重視する。

## 外部サービスを接続して初めて実行できること

- Search Consoleの検索クエリ別・日別流入を取得する
- A8.netの提携・広告掲載URL・成果レポートを見る
- Vercelの本番変数・デプロイログ・請求額を確認する（現在の連携は403、チームアクセス再承認が必要）
- 旅行会社の正式な予約・料金APIを接続して「同条件・税や手数料込みの実際の最安値」を比較する

**APIトークン、ASPログイン情報、非公開広告主報酬条件はGitHub Issueに置かないでください。**
