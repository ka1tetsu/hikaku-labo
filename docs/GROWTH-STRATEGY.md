## 1. 結論（先に）

1. **収益 = 訪問数 × サイト内クリック率 × 申込率 × 報酬単価 × 承認率**。今いちばん足りないのは「訪問数」。クリック率の改善はその次。
2. 訪問数の柱は **検索（SEO）**。ただし「格安SIM おすすめ」のような大きなキーワードは価格.com・mybest・大手メディア・公式が占めており、新しいサイトが数か月で勝つのは難しい。
   → **ツールでしか答えられない、具体的で長い検索語（ロングテール）** から取る。例：「関西 光回線 au」「40代 年会費無料 クレジットカード 還元率」「ahamo LINEMO 比較 10GB」。
3. 収益単価が高く、条件で答えが決まりやすい **光回線 → 格安SIM** を最優先で深掘りする。クレジットカード・保険は単価が高い一方、信頼性の審査が厳しい分野（YMYL）なので、運営者情報・出典・更新体制を整えてから伸ばす。
4. **独自ドメインへの移行を最優先で決める**。`hikaku-labo.vercel.app` のまま評価や被リンクを積み上げると、後で移すときに損をする。
5. 計測を整え、**ページ別のクリック率** を毎週見て、配置と文言を1か所ずつ改善する（今日、閲覧数の記録を追加済み）。

## 3. 誰が・なぜ来るのか（検索の意図）

比較サイトに来る人は、ほぼ次の3段階のどこかにいる。段階ごとに「刺さるページ」と「クリックされる理由」が違う。

| 段階 | 検索例 | 必要なもの | 比較ラボの武器 |
|---|---|---|---|
| ① 悩みに気づいた | 「スマホ代 高い」「固定費 見直し」 | 何から手をつければいいか | AIコンシェルジュ、/life/ ハブ |

## 4. 集客チャネル別の分析

### 4-1. 検索（SEO）— 本命。積み上がる資産

- **大きなキーワードは後回し**。強いサイトが上位を占めていて、YMYL分野では新しいサイトの評価が上がるまでに時間がかかる。
- **勝てるページの型**（すべて「実データ＋条件別の答え」があること。中身の薄い大量生成は逆効果）：
  1. **2社比較ページ**：「ahamo vs LINEMO」「楽天カード vs PayPayカード」。格安SIM 9社なら36通り。両社の公式料金表と、使い方別の結論を出す。
  2. **地域×スマホの光回線ページ**：「関西でauを使っている人の光回線」。10地域×5キャリア。提供エリアとセット割で答えが変わるため、ツールの結果をそのまま文章化できる。
  3. **条件別ページ**：「10GBで一番安い格安SIM」「40代から作れる年会費無料カード」。
  4. **型番の価格ページ**：人気商品の型番ごとに全ショップ比較を静的ページ化（毎日価格を更新する仕組みが必要。将来の課題）。
- **鮮度**：料金系は「2026年10月」のように確認日を明記し、毎月更新する。古い情報は順位も信頼も落とす。
- **内部リンク**：ハブ（/life/）→各比較→2社比較→公式、の階層をつなぐ（今回「あわせて見直す」を追加済み）。
- **被リンク**：「主要9社の料金推移」「光回線のエリア早見表」のような **引用されやすい独自データ** を作り、SNSや note で紹介する。

### 4-2. SNS（X / Instagram / TikTok / YouTube Shorts）— 立ち上げ期の初速

- 検索で評価されるまでの数か月の **初速づくり**。
- 発信テーマ：「スマホ代をこの条件で診断したら月◯円下がった」「光回線はセット割で選べ」「年会費無料カードは“基本還元率”で比べろ」など、**ツールの結果をそのままネタにする**。
- 1投稿に1つのツールへのリンク。OGP画像が出るようになったので、リンクのクリック率が上がる。
- 注意：ASPによってはSNSでの直リンク・広告の掲載方法に規定がある。**比較ラボのページにリンクし、比較ラボ内で広告に送る** のが安全。

### 4-3. note（既存の資産を流用）

- すでに note で記事を書いているなら、記事末尾に「条件を入れて比較できる無料ツール」として各ページへリンクする。
- 有料記事の読者は「お金に関心が高い層」で、通信費・カードの見直しと相性がよい。

### 4-4. 広告（リスティング・SNS広告）— 慎重に

- 光回線・カードは検索広告のクリック単価が高い分野。さらに **ASPの多くが「リスティング出稿禁止」「指名キーワード出稿禁止」** を定めているため、プログラムごとの規約確認が必須。
- 方針：最初は使わない。成果データが取れ、1件あたりの報酬と申込率がわかってから、規約で許されたプログラムだけ小さく試す。

### 4-5. 再訪問（リピート）

- 価格比較は「値下がりを待つ」人が多い。**値下がり通知（メール/LINE）** は将来の有力機能（要：保存先とバッチ処理）。
- 旅行は季節（GW・夏休み・年末年始）に合わせた特集で再訪を作る。

## 5. サイト内クリック率（CTR）を上げる設計

### 5-1. 計測の定義（今日から取れる）

- `hikaku_view`：ページ閲覧（ページIDのみ）
- `hikaku_outbound`：外部リンクのクリック（section / merchant / placement / sponsored）
- **ページCTR** ＝ そのページの outbound 数 ÷ view 数
- **配置別CTR** ＝ placement ごとの outbound 数 ÷ view 数（例：`sim-toppick` と `sim-rank` の比較）
- ASP側の **申込率** ＝ ASPの成果数 ÷ ASPのクリック数（ASP管理画面で確認）

### 5-2. クリックされる理由をつくる（実装済み／今後）

| 施策 | 理由 | 状態 |
|---|---|---|
| 結論ファースト（いまの条件での1位を最上部に） | スマホでは比較表まで読まれない | **実装済み**（/sim/ /hikari/ /card/） |
| 条件で順位が変わる | 「自分向けの答え」は押される | 実装済み |
| 理由と注意点を並べる | 注意点も書くと信頼され、申込後のキャンセルも減る | 実装済み |
| 確認日・出典 | 「この料金は本当？」の不安を消す | 実装済み |
| CTAの文言を「公式サイトで条件を確認」に | 申し込みより心理的ハードルが低い | 実装済み |
| 関連ページへの導線 | 1訪問で複数の見直しにつなげる | **実装済み**（あわせて見直す） |
| AIコンシェルジュ | 迷っている人を比較ページへ戻す | 実装済み |
| 2社比較・地域ページ | 検索意図にぴったり合う着地ページ | 次の作業 |
| 値下がり通知 | 再訪とクリックの機会を増やす | 将来 |

### 5-3. やってはいけないこと

- 偽のカウントダウン、根拠のない「No.1」、実在しない口コミ、報酬額での順位操作。景品表示法・ステマ規制・ASP規約違反のうえ、信頼を失い長期的に損をする。
- 広告であることを隠す。比較ラボは「PR」表示と開示文を全ページに入れている。

### 5-4. 改善の回し方（A/Bテストの考え方）

- 1回に変えるのは1か所（CTAの文言、位置、1位ボックスの有無など）。
- 判断には十分な数が必要。目安として **1パターンあたり閲覧1,000回以上** たまってから比べる（それ未満の差は偶然の可能性が高い）。
- 週1回、ページ別CTRと配置別CTRを表にして、下位のページから手を入れる。

## 6. 収益の見込みを考える式（数字は仮定）

```
月の確定報酬 ＝ 月間閲覧数 × サイト内CTR × 申込率 × 1件あたり報酬 × 承認率
```

**計算例（すべて仮定の数字。実際の値はASPと計測で置き換えること）**

| 仮定 | 値 |
|---|---|
| 光回線ページの月間閲覧数 | 3,000 |
| サイト内CTR（公式へのクリック） | 15% |
| 申込率（クリック→申込） | 2% |
| 1件あたり報酬 | ASPの掲載額を使う（ここでは X 円と置く） |
| 承認率 | 70% |

→ 3,000 × 0.15 × 0.02 × 0.7 ＝ **月6.3件 × X円**。
CTRを15%→20%にすると8.4件、閲覧数を2倍にすると12.6件。**閲覧数の改善の方が効きやすい**。

## 7. 分野ごとの優先順位

| 優先 | 分野 | 理由 | 必要なこと |
|---|---|---|---|
| 1 | 光回線 | 報酬単価が高い傾向。「セット割×エリア」で答えが決まり、地域ページで勝ちやすい | 各社プログラムのASP提携、地域×キャリアのページ |
| 2 | 格安SIM | 乗り換え需要が大きい。料金が明確で比較ツールと相性がよい | ASP提携、2社比較ページ、毎月の料金更新 |
| 3 | 商品の価格比較 | 料率は低いが、件数が出やすい。既存IDで今すぐ収益化 | Yahoo! Client IDの設定、人気型番の静的ページ |
| 4 | クレジットカード | 報酬単価は高いが、競争とYMYL審査が最も厳しい | 運営者情報・編集方針の整備後に深掘り |
| 5 | 保険 | 報酬は高いが、保険業法上「商品の比較・推奨」は避ける必要 | 無料相談サービスの紹介に限定（実装済みの方針） |
| 6 | 旅行 | 料率は低め・季節性あり | 季節特集、AIコンシェルジュからの送客 |

## 8. 法令・規約のチェックリスト（オーナー確認）

- [ ] **ステマ規制（景品表示法）**：広告の明示。比較ラボは「PR」表示と開示文で対応済み。
- [ ] **景品表示法（有利誤認）**：料金は割引前・条件を明記。「最大◯%」だけを強調しない（対応済みの方針）。
- [ ] **電気通信事業法**：通信サービスの「契約の媒介等」をする者には届出義務がある。アフィリエイト広告が該当するかは、総務省「媒介等業務受託者届出マニュアル」の対象範囲を確認する。
- [ ] **保険業法**：特定の保険商品の比較・推奨は「保険募集」に当たるおそれ。比較ラボは商品の比較をせず、相談サービスの紹介に限定。報酬を受ける形態は専門家に確認する。
- [ ] **ASP規約**：自分でのクリック・申込の禁止、リスティング出稿の規定、掲載文言の指定（公式の表記どおりにする）。
- [ ] **Amazonアソシエイト**：価格を表示するなら公式API（PA-API）経由が必要。比較ラボはAmazonの価格を表示せず、検索リンクのみ（対応済み）。

## 9. 90日の実行計画

### すぐ（オーナー作業）
1. 独自ドメインを取得してVercelに設定（例：`hikaku-labo.jp`）。canonical・sitemap・OGPのURLを新ドメインに置換。
2. Google Search Console に登録し、sitemap.xml を送信。
3. ASPに申請：光回線・格安SIM（A8.net／アクセストレード／バリューコマース／もしも等）。承認された計測URLを `VITE_AFF_URL_<ID>` に設定。
4. Yahoo!デベロッパーの Client ID を `YAHOO_SHOPPING_CLIENT_ID` に設定。
5. 運営者情報・編集方針・お問い合わせページの内容（運営者名・連絡先・情報更新の方針）を用意。

### 1か月目（開発）
- 2社比較ページ（格安SIM・光回線から）と地域×キャリアの光回線ページ。
- 料金データの月次更新手順を決め、確認日を更新。
- SNSで週3回、ツールの診断結果をネタに発信。

### 2〜3か月目
- ページ別・配置別CTRを週次で確認し、下位ページの改善（1か所ずつ）。
- 引用されやすい独自データ記事（料金推移・エリア早見表）。
- 人気型番の価格ページと値下がり通知の設計。

| 検索の表示回数・クリック数・掲載順位 | Search Console |
