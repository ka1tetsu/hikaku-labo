# Vivlica 全サイトの文章品質とImpeccableデザイン監査（2026-10-29）

## 取り込んだ考え方

参照した考察は「AIっぽい語尾の置換」と「読者の判断材料が増える編集」を分けるものです。https://zenn.dev/acntechjp/articles/ を含む紹介内容をレビューの考え方として利用し、元記事の文章を無断複写していません。

サイトの成果は「AIで作ったことを隠す」ではなく **データソース・比較条件・欠落データ・計算の意味・選ぶ理由** が自然に読める状態にすること。見た目だけを変える脱臭作業や検出回避を目的にしません。

## 実装した範囲

- 既存ルートを使う商品、ITサービス、旅行、通信/カード、企業データリンクのUI設計方針を `PRODUCT.md` と `DESIGN.md` に記録
- 共有ヘッダーの折りたたみ「情報源」「計算・比較方法」「含まれない情報」「最後に確認すること」。メインのReactページとSSRを使う各種比較ページに適用
- 非LLMのルールベース・ブラウザ内アシスタントを「条件検索アシスタント」として正確に説明
- 商品ページの「全ての価格は実データ」「参加中なら必ず紹介料が発生」のような過度な一般化を除去
- サイトのライティング責任と出典検査の原則を編集方針へ追加
- 主な各ページのスタイルで英字フォントInterを削除し、Noto Sans JPを基本に統一（新しいフォントファイルは再配布しない）
- 未検証のAI記事大量生成を遮断。明示的に `--drafts-only` を指定した場合のみ公開ディレクトリから離れた `content/drafts/editor-review-required` に出力し、一次情報による検査を必須に

## Impeccable

公式: https://github.com/pbakaus/impeccable 、https://impeccable.style/docs/detector/

- CLIは **impeccable@4.7.0** に固定。最新版の規則数・挙動が変わってもCI結果を比較可能にするため。
- `npm run audit:design` で `src/`、静的 `guides/`、主要入口HTML、記事CSSを同時走査。
- `.github/workflows/impeccable.yml` はPRとmainへの更新時に同じCLIを2回実行し、変更前Git commitとの比較レポートと検出JSONをActions artifactへ保存。
- Impeccableが終了コード2を返した場合は通常の違反検知。CIでは **変更前より増えたファイル×ルールの主検出件数のみ** をブロックする（現状の既存違反を隠さない）。
- 途中のコマンドエラーやJSON解析失敗は失敗として扱い、結果を誤って「問題なし」にしない。
- 0件なら「検出器で新しい主検出がなかった」という意味で、完全なアクセシビリティ保証やUX完成の証明ではない。
- 大きな変更は375px・768px・1280pxで、UIテキストの折り返し、セマンティクス、コントラスト、実際のタッチ領域を目視確認すること。
- `.impeccable/config.json` はignore全空・telemetry無効。DESIGN.mdとの自動トークン照合だけは既存CSSの移行前なので一時無効。今後トークン移行が済んだら有効化する（検出器全体を無効化したわけではない）。

ローカルのコーディングエージェントへ追加する場合、レビューしたリポジトリで次を実行できます。

```sh
npx impeccable@4.7.0 install -y --providers=codex --scope=project --no-hooks
# 使っている対応エージェント内で /impeccable init
npm run audit:design
```

公式の **initは通常CLIの `npx impeccable init` ではなく、エージェントの `/impeccable init`** です。既存の `PRODUCT.md` と `DESIGN.md` を尊重して更新すること。エージェント用フックを追加する場合は、公式のセキュリティ注意に従い動作をレビューしてから信頼すること。

## 次に重要なこと

Impeccableの静的スキャンを通しても、実際に読者へ価値を生むのは「体験者の独自観察」「予約日時と同等条件の比較」「実際の料金差」「一次資料の引用」「理由と例外」です。機械が検出するUIパターンが消えたことだけを成果とみなしません。本文の変更加工は出典確認と併用してください。
