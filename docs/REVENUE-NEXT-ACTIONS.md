# 収益化の実行状況と本人接続が必要な作業

確定報酬・広告主の承認状態・運営費の実績にはアクセスしていません。掲載リンクやクリックを利益として扱いません。

## 実測した状態

- 本番: https://hikaku-labo.vercel.app 。GitHub/Vercel連携で公開済み。
- トップの初期HTMLには楽天・Amazon・Yahoo!の成果リンクを計12件、旅行ページには楽天1件とYahoo!トラベルのA8原文素材2件を確認。リンク先へはアクセスしていません。
- 初期表示のSIM・ITページには成果リンクを検出できません。別の条件や広告承認の有無まではHTMLだけでは断定できません。
- 楽天の商品APIは403。診断では既存のApplication ID・Access Key・Affiliate IDの設定があり、Origin/Referer付きのリクエストが HTTP_REFERRER_NOT_ALLOWED で拒否されました。キーを再発行する前に許可サイト設定を確認します。
- Yahoo!の自動価格比較は未接続です。現在、実売価格の自動比較は成功していません。ショップへの検索リンクで案内を継続します。
- 有料AI生成は無効で、通常の比較・診断・旅行提案は有料AIを使いません。
- vivlica.com はCloudflareのネームサーバーを使用していますが、GitHubランナーからWeb接続先の名前解決ができませんでした。

## 実行・自動化する作業

- 登録サイト制限が続く楽天への問い合わせを、各ウォーム関数で短時間停止し、修正後に再試行できるようにします。
- 診断APIの通常アクセスでは外部APIを呼ばず、秘密値の先頭文字も返しません。詳細プローブは任意の管理者認証が必要です。
- 商品の他店検索へ、広告文の先頭単語ではなく型番・ブランドを引き継ぎます。架空の料率で行き先を決める処理を削除します。
- 自動価格取得ができない場合の表示を、単なる「出品がない」と区別します。
- `npm run audit:live` で本番ページ、初期HTMLの成果リンク、サイトマップ、計測API、価格APIを確認します。広告リンク・計測画像にはアクセスせず、売上を推定しません。
- GitHub Actionsの公開時・週次監査でJSONレポートを保存します。保存期間14日。新しいコミットの公開完了を確認してから検査するため、旧版の成功を新しい公開の成功と取り違えません。

## 本人の接続・契約が必要なもの

### 1. 楽天の登録サイト

https://webservice.rakuten.co.jp/app/list の対象アプリで、稼働中の `https://hikaku-labo.vercel.app/` が許可されているか確認してください。楽天アフィリエイト側の媒体登録も確認します。新しい秘密値をチャットやリポジトリに送る必要はありません。将来Vivlica.comへ切り替える際は、新ドメインも事前登録してください。

### 2. ドメイン接続

Vercel: https://vercel.com/ka1tetsus-projects/hikaku-labo/settings/domains
Cloudflare: https://dash.cloudflare.com/

Vercelへvivlica.comを追加し、プロジェクトに表示された正確なDNSレコードをCloudflareへ反映します。レコード値を推測して設定しません。所有確認とHTTPS・主要ページの応答確認後に正規URL・旧ドメイン転送を切り替えます。

### 3. 成果報酬と検索流入

- ASPで掲載可能なサービスの提携を確認し、承認済みの成果URLまたは原文HTMLを取得します。契約・申請を本人の代わりに確約しません。
- 公開URLは `VITE_AFFILIATE_LINKS` のJSONにまとめられます。原文HTMLが必須のA8素材はHTMLのまま設定します。広告掲載の有無で比較順位を変えません。
- https://search.google.com/search-console/ の既存プロパティにアクセスできる場合は、現在のサイトマップ https://hikaku-labo.vercel.app/sitemap.xml を送信します。ドメイン切替後は所有確認と新サイトマップの送信・移転処理を行います。
- ASPの確定報酬と実際の運営費を同期間で確認し、`report:revenue` へ集計値を入力します。データがない期間の利益は不明のまま扱います。

## 判断の順序

1. まず商品APIの登録サイト制限を解除し、取得できた実データと紹介URLの有無を確認する。
2. すでに利用者を送っているサービスのうち、読者の条件に合う承認済み素材を設定する。
3. Search Consoleの実クエリと、ページ別の送客操作を同期間で比較する。
4. 確定報酬と運営費の差を確認してから集客費・有料APIの予算を検討する。

自動監査の成功は、利益が出たこと・ASPに承認されたこと・価格APIが正常なことと同義ではありません。レポートの findings を確認してください。
