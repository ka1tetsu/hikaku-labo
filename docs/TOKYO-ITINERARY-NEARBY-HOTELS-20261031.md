# 東京のモデルコースに周辺ホテルを紐付ける（2026-10-31）

## 利用者の動線
`/travel/?destination=tokyo&nights=2&pace=standard&style=classic#recommendations` で「東京・王道を楽しむ 2泊3日」を表示。宿泊のある各日の立ち寄り先に合わせて、宿泊拠点候補を2施設ずつ並べる。
- 1日目「浅草・浅草寺」「上野公園」→ **浅草・上野エリア**：リッチモンドホテルプレミア浅草／浅草東武ホテル。
- 2日目「東京駅・丸の内」「渋谷・表参道」→ **東京駅・丸の内エリア**：ホテルメトロポリタン丸の内／東京ステーションホテル。**渋谷側に徒歩で近いとは主張しない**。
- 3日目は出発日で宿泊がないためホテルの新規候補を表示しない。日帰りは候補なし。1泊なら1日目のみ。
- 旅のスタイルや訪問先が変わった場合、登場する地名（浅草／東京駅／新宿）に応じて候補エリアを変える。人手で検証したホテルがない都市・エリアでは、適当なホテル名を捏造せず予約サイトの**都市検索リンク**を表示する。

収益/広告による選定順位ではなく、編集部が公式立地を確認できる都市内の候補。価格帯の順位、旅行日程中の空室、公式レビュー平均などは一切捏造しない。

## 宿泊条件とリンク
- 各ホテルの「公式サイトで立地確認」「地図」は非広告リンク。
- 「宿泊日で探す」は既存 `buildStayLinks()` のBooking.com検索URLに**ホテル名＋東京**を指定し、旅行日程全体のチェックイン・チェックアウト、大人の人数、部屋数を引き継ぐ。候補ホテルの空室を確認できるという保証ではなく、予約サイトが実際の検索結果を返す。適法に設定されたアフィリエイトIDがある場合のみPRを表示。
- どの日を選んでも**全泊同じホテルの検索**を提案。日替わりのホテル移動を要求しない。ホテル名を1日目と2日目で比較して旅行全体の拠点を決められる。
- 地図は公式名でGoogle Maps検索を開く。観光地点とホテルの徒歩距離・移動時間は計算しておらず、ユーザーは現地マップで確認する。
- 東京以外の目的地では、既存の公式予約検索サイトへ都市名・日程を渡し、未検証ホテル名は表示しない。
- OTA検索の結果、価格、空室、口コミは取得していない。掲載情報は立地とホテルの実在確認。予約・支払は予約先で行う。

## 検証
- 東京2泊3日のDay1/Day2の宿泊エリアとホテル名、Day3/日帰りで宿泊候補なし。
- 公式情報がHTTPSドメインにあり、候補が6件で重複せず、架空の価格・星数を持たない。
- Booking.com検索条件に宿泊日・大人人数・室数が引き継がれる。新しい旅行先・1泊・0泊を切り替えて古い宿が残らない。
- 375pxスマートフォンでホテル情報が横にはみ出さず、外部リンクのPR表示・アクセシビリティが保たれる。
