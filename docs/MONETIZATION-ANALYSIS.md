## 集客・成約・利益について残る検証

1. **集客**：Search Consoleで表示回数、検索クリック、インデックス、ページ・クエリ別の実績を取得する。流入ゼロなら、CTA変更だけでは解決しない。現状で流入不足を断定できる数値はない。
2. **意図との適合**：検索クエリと着地記事を比べる。記事→比較の操作数、比較→サービスの送客数を同期間で見る。集計は操作回数なので、利用者の離脱率とは呼ばない。
3. **成果リンク**：送客実績がある通常リンクのサービスから提携可否と素材を確認する。報酬の大きいサービスへ無条件に順位を変えない。楽天・Amazon・ValueCommerceの既存公開IDについても所有・有効性を本人のASPで確認する。
4. **成約**：ASPの実クリック・発生成果・確定成果を照合する。送客があって確定報酬がない場合も、否認・計測漏れ・読者条件の不適合・成果の確定待ちを区別する。
5. **ドメイン**：Vercel設定は稼働中の`hikaku-labo.vercel.app`をビルドの正規URLに指定している。ローカル既定値は移管先`vivlica.com`。DNS・TLS・媒体登録を確認するまでは切替を進めない。実際に配信されたcanonicalは自動監査で確認する。
6. **商品API**：過去の登録サイト拒否が続いているか、本番監査で再確認する。既存のキー・許可サイト設定を確かめてから修正する。APIが止まっても検索リンクは使えるようにする。
7. **内容の信頼性**：運営主体・問い合わせ先の確認、公式価格の定期確認を続ける。本人情報や未確認の料金を補完・創作しない。今の63ページが検索需要に合うか確認する前に、薄い記事を大量生成しない。
8. **利益**：同期間の確定報酬−運営費を確認する。広告費・有料AI・有料データ取得の追加は実績と予算を見て決める。今回の変更は有料サービスを追加していない。

## 自動化した運用

`.github/workflows/production-affiliate-audit.yml`は、公開後・毎日12:00日本時間・main上の手動実行で収益導線を検査します。変更をmainへ反映するまでは新しい定期処理は動きません。GitHubのスケジュール実行は遅延・停止することがあるため、連続稼働の保証ではありません。

- 初期HTMLの紹介導線、公開先とcanonicalの一致、価格APIの実データ、計測APIの不正入力拒否を確認。
- 商品・通信・光回線・カード・IT・旅行を確認。紹介リンクや広告計測画像を開かず、クリック・売上を発生させない。
- 実行概要に要対応一覧を表示し、JSONを30日間保存。
- `--require-monetization`では、要対応があればジョブを失敗として通知。ページのHTTP成功だけで緑にしない。
- 接続できない場合は利益化失敗やAPI故障を推測せず、監査未完了として報告。

```sh
export PATH=/workspace/.cloud-tools/node_modules/.bin:$PATH
cd /workspace/hikaku-labo
SITE_ORIGIN=https://hikaku-labo.vercel.app npm run audit:affiliate
npm run audit:live -- --origin https://hikaku-labo.vercel.app \
  --output /tmp/vivlica-readiness.json --summary /tmp/vivlica-readiness.md \
  --require-monetization
```

成功時も`configured_not_verified`であり、利益発生を意味しません。ローカルの広告監査にVercelのビルド変数が自動注入されるわけではありません。

このクラウド環境のようにHTTPSプロキシが必要な場合、Node.js 22では `node --use-env-proxy scripts/audit-live.mjs` に上記の引数を渡して実行します。プロキシを使用しないfetchのDNSエラーを、本番サイトの停止と取り違えないでください。

記事の`guideComparisons`は比較画面への操作数です。閲覧はあるが比較移動・送客がない記事は、既存の`report:revenue`の`nextActions`に出ます。過去の`sim-vs`・`hikari-area`ログも読めますが、個別ページへ遡って配分しません。

```sh
npm run report:revenue -- /tmp/vercel-events.ndjson \
  --from 2026-10-01T00:00:00+09:00 --to 2026-11-01T00:00:00+09:00 \
  --finance /tmp/settlements-and-costs.json
```

精算JSONの形式は[公開・収益運用](VIVLICA-LAUNCH.md)を参照してください。未提供の利益は`null`です。ログの継続エクスポートやASPの精算取得は未接続です。DB・分析サービス・各ASPの認可が必要な部分は、認可とデータ取得方法を確認してから接続します。
