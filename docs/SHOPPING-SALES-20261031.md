# 比較ラボ｜商品比較で購入先クリックを増やす実装と運用（2026-10-31）

## 実装済み（本変更）
- 最小の商品価格と、APIに「送料無料」と表示された別の出品を、**同じJAN/型番照合候補に限り**購入判断の入口に表示する。価格差と送料の不確実性を見せる。自社の広告報酬率は選択ロジックに含めない。
- ソースが部分停止したとき、取得できたYahoo!の結果を活かしながら、取得できない楽天を比較対象に含めていないことを明示する。
- Yahoo!商品検索APIの PayPayポイント（期間限定）`point.lyLimitedBonusAmount` を取得。会員限定ポイントを一般の購入者に足し込まず、現金支払額と区別する。送料コード3は「条件付き送料無料」とし、0円とはみなさない。
- 匿名の決定ファネル（`product_search`, `product_results_ready`, `product_offer_selected`, `product_target_saved`）を既存 `/api/track` で計測。検索語、出品URL、価格、個人情報は送信しない。既存の `compare-offer`、`compare-shortlist`、`decision-cash`、`decision-shipping` のクリック計測を使う。
- 比較ページのtitle/descriptionから「全ショップ最安」「購入時の実質価格」といった未検証の主張を削除する。
- 新しいNodeテストと、375px幅のChromium回遊テストを追加。

## 事実確認と運用上の制限
- Yahoo!公式 商品検索v3: https://developer.yahoo.co.jp/webapi/shopping/v3/itemsearch.html
- Yahoo!公式 アフィリエイト: https://developer.yahoo.co.jp/webapi/shopping/affiliate.html
- 2025年以降のポイントは旧`amount`や`bonusAmount`が0固定化。期間限定項目と会員限定項目の区別が必要。
- Yahoo!の1クエリ/秒等の利用制限と、使用目的・データ保持の規約を遵守。検索APIデータをスクレイピングまたは無制限保存しない。
- **APIで商品を取得できた＝報酬が発生する、ではない。** バリューコマース側でサイト登録・Yahoo!ショッピング案件承認・当該サイト向けの`sid`/`pid`所有を確認する。現在の既定IDを利用者本人に紐づくと自動的に断定しない。
- 楽天API 403 が残っている間、楽天価格が0件でも「全モール比較」と言わない。登録サイト・アフィリエイトパラメータ・環境変数を調査する。
- 顧客の成約件数、確定報酬、利益はASP側の実績で初めて確認できる。UIクリックとASP確定成果を同一視しない。

## 収益検証（1〜2週間を同条件で観察）
1. 検索ページ閲覧数 / `product_search` / `product_results_ready` / `decision-*`クリック数を日別に集計し、検索後の送客率を把握する。検査用ボットや重複イベントは除外または別に扱う。
2. バリューコマース側で同期間のYahoo!ショッピング承認済み広告IDのクリック・発生成果・確定報酬を確認する。異なる計測体系・アトリビューションに注意する。
3. 送客は増えたが承認報酬が出ない場合は、`sid`/`pid`の所有・提携状況、サイト掲載URL、リンクの遷移先、報酬対象外条件を先に検査する。
4. 利用者が出品を選ばない場合は、型番一致失敗率・商品の画像欠損・検索語の曖昧さを個人情報を取らずに調査し、よりよい絞り込みを検討する。
5. SEOはGoogle Search Consoleに`/compare/`と既存サイトマップを登録し、掲載可否と検索クエリを閲覧する。価格の自動取得できないモールをSEO構造化データで誤って販売元としない。
