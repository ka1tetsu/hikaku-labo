# アクセス・成果レポート（/admin/）

比較ラボの訪問者数・ページビュー・流入元・外部リンクのクリック・成果（購入・申込）・報酬を、
1つの画面で確認するための仕組みです。外部の解析サービスやCookieは使いません。

## できること

| 指標 | 出どころ | 備考 |
|---|---|---|
| 訪問者数（ユニーク） | サイト内の計測（`/api/track`） | 同じ人の同じ日の訪問は1人。日をまたぐと別に数える。ロボットは除外 |
| ページビュー（ページ別） | 同上 | トップ、/sim/、2社比較ページ（まとめて1行）など |
| 流入元 | 同上 | Google・Yahoo!・X・LINE・直接など。参照元のURLや検索語は保存しない |
| 外部リンクのクリック（ショップ別・掲載位置別） | 同上 | 広告（PR）リンクかどうかも区別 |
| クリック率 | クリック ÷ ページビュー | |
| 成果件数・報酬額 | **ASPの管理画面の数字を入力** または ASP からのポストバック | 楽天・A8.net・Amazon などは、誰が買ったかをサイト側に教えないため |
| 成約率 | 成果 ÷ クリック | ショップ名をクリックのIDと揃えると、同じ行で計算される |

期間は7日・30日・90日（日本時間の日付で集計）。日別の数字はCSVで保存できます。

## 初回の設定（約10分）

1. **データの保存先をつなぐ**
   Vercel のプロジェクト → **Storage** → **Create Database** → Marketplace の **Upstash for Redis** を選び、
   このプロジェクトに接続します。環境変数 `KV_REST_API_URL` と `KV_REST_API_TOKEN` が自動で追加されます。
   （Upstash で直接作った場合は `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` を手で設定しても動きます）
2. **管理トークンを決める**
   Vercel → Settings → Environment Variables に `ADMIN_TOKEN` を追加します（16文字以上のランダムな文字列）。
   例：ターミナルで `openssl rand -base64 24` を実行して出た文字列。
3. **再デプロイ**（環境変数は再デプロイ後に有効になります）
4. `https://<サイトのドメイン>/admin/` を開き、管理トークンを入力します。

保存先が未接続のあいだも、これまでどおり Vercel の Function Logs には記録されます（集計画面は使えません）。

## 成果（購入・申込）の入れ方

- **手入力**：/admin/ の「成果を記録する」に、日付・ショップ名・件数・報酬額を入れて保存。
- **まとめて貼り付け**：ASPのレポートを表計算ソフトで開き、`日付, ショップ・案件名, 件数, 報酬額` の4列にしてコピー＆ペースト。
  `2026/10/01` や `¥1,240` の形式も読めます。1行目の見出しは無視されます。
- 同じ日付・同じショップ名で入れ直すと**上書き**されるので、月末に1か月分を入れ直しても二重に数えません。
- ショップ名は、クリック計測と同じID（`rakuten`、`amazon`、`yahoo-shopping`、`rakuten-mobile` など）にすると成約率が出ます。
  IDの一覧は `src/shared/outboundSchema.js` と `src/services/catalog.js` にあります。
- 報酬額は「発生」ベースの見込みです。否認・キャンセル後の**確定報酬は必ずASPの画面で確認**してください。

### ポストバック（任意）

成果が発生したときに指定URLへ通知する機能（成果通知・ポストバック）を持つASPなら、自動で記録できます。
環境変数 `POSTBACK_KEY`（16文字以上）を設定し、ASPの通知先に次のURLを登録します。

```
https://<サイトのドメイン>/api/stats?postback=<POSTBACK_KEY>&merchant=<ショップID>&count=1&amount=<報酬額>
```

`amount` などの差し込み変数の書き方はASPごとに違うので、各ASPの説明に合わせてください。
ポストバックの数字は手入力の数字と**足し算**されます。同じASPでポストバックと手入力を両方使わないでください。

## プライバシーと保存する内容

- 保存するのは**日ごとの合計値だけ**です（ページ別ビュー数、流入元の種類別の数、ショップ×掲載位置別のクリック数、成果件数・報酬）。
- 訪問者数は、IPアドレスとブラウザ情報を**日ごとに変わる秘密の値**で暗号化したものを HyperLogLog（人数を推計する仕組み）に入れて数えます。
  元のIPアドレスやブラウザ情報は保存されず、日をまたいだ追跡もできません。
- Cookie、端末ID、検索キーワード、参照元URL、商品名、広告URLは送信・保存しません。
- 訪問者数の推計誤差は1%程度です。広告ブロッカーを使う人などは計測されないため、実際より少なめに出ます。
- 訪問者の推計データ（`uv` キー）は400日で自動削除されます。合計値は削除されません。

## 費用の目安

1ページビューあたりRedisのコマンドを6回、1クリックあたり2回使います。
月1万ページビュー・クリック1,000回なら約6.2万コマンドです。Upstash の無料枠の上限は変わることがあるので、
[Upstash の料金ページ](https://upstash.com/pricing/redis) で確認してください。

## ほかのツールとの使い分け

- **検索キーワード・検索順位**：Google Search Console（このレポートは検索語を記録しません）。
- **確定報酬・否認率**：各ASPの管理画面。
- **表示速度・Web Vitals**：Vercel の Speed Insights（任意）。
