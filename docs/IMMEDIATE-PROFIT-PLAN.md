# 短期の利益改善：実行内容と残る作業

2026-10-25。直前の[原因分析](MONETIZATION-ANALYSIS.md)に続く追加調査です。

## 最初に改善する箇所

最短の施策は、すでにある商品・旅行の紹介先へ、読者の入力を失わずに案内することです。新しい広告費・有料AI・記事の大量生成は追加していません。

ただし訪問数、ASPの確定報酬、請求額は未接続です。「変更直後に何円増えた」「最も売れる案件」を断定できる実績はありません。実利益は同期間の確定報酬から実際の運営費を引いて確認します。

## 今回修正した取りこぼし

| 問題 | 改善 | 狙いと検証方法 |
| --- | --- | --- |
| 商品APIが503になるまでショップの検索導線が出ない。通常検索は結果より上の大きな診断欄にとどまる | 入力直後から楽天・Amazon・Yahoo!の検索リンクを表示し、検索結果へスクロール。取得中・失敗時・0件でも残す | APIが止まっている間も比較・購入先を探せる。`search-direct`の操作を同期間の閲覧数と比較 |
| 旅の予算で人数を変えても予約欄のローカル状態が2名のまま。部屋数も予算入力と異なる | 予算・予約欄の人数、部屋数、チェックインを共有 | 条件の再入力と誤検索を減らす。10名・4室をBooking.com検索URLで確認 |
| 予約日の`min`が「今日」ではなく「30日後」 | 今日以降を選べるように修正 | 直近旅行を検討する人の操作を妨げない。明日の宿泊日をブラウザで確認 |
| 予算結果の次の一手が、行き先を引き継がないYahoo!の広告だけ | 予算結果から行き先を反映した宿泊検索へ案内。対応するサイトには日付・人数・部屋数も渡す | 予算計算から予約条件確認への距離を縮める。`budget-stays`別に集計 |
| 海外や日帰りでも国内宿泊の広告が表示される | 国内宿泊広告は国内かつ1泊以上に限定。日帰りは宿泊検索を表示しない | 読者の目的に合わない導線を減らす。海外・日帰り・国内泊ありを切替検証 |
| 世界の宿泊比較カードがトップページへ送るだけで、既存の楽天紹介IDも使わない | 既存設定がある楽天は対象の国内／海外検索へ。Booking.com等も対応する検索条件を引き継ぐ | すでにある設定を利用する。未提携リンクを広告にはしない |
| 旅行先が決まっている人も長いモデルコース一覧を経由する | 上部から宿・航空券、予算へ移動できる導線を追加。宿泊を初期表示 | 選び終わった人の次の操作を短くする。成約率が上がったかはASP実績で別途確認 |

楽天の宿泊キーワード検索は行き先のみ引き継ぎます。未確認の日付パラメーターを推測して付けず、日付・人数・部屋数は予約先で再設定することを明示しました。A8の原文HTML・画像・リンクは変更していません。

## 本番で確認した外部依存

調査開始時の本番監査では、主要ページ・canonical・サイトマップ・計測APIは正常、商品検索は503、価格比較は楽天`error`・Yahoo`disabled`で0件でした。通信・光回線・カード・ITの初期HTMLには成果リンクがありません。旅行では既存の楽天1件とYahoo!トラベルのA8素材2件を確認しています。

これは「売上がゼロ」の証拠ではありません。掲載状況・API応答の検査であり、ASP精算データを見たものではありません。

次に行う外部作業は、以下の順です。

1. **既存の承認と媒体登録を照合**：楽天・Amazon・ValueCommerce・A8の公開IDの所有、掲載サイト、広告主条件を本人の管理画面で確認。既存のキーは設定済みのため、むやみに再発行しない。
2. **楽天の拒否原因を修正**：受動診断ではApplication ID・Access Key・Affiliate IDの設定と形式は有効。許可サイト、Origin/Referer、プロバイダー応答を認証済みの運用画面で確認。503の表示だけから原因を断定しない。
3. **送客がある通常リンクに正式な成果素材を設定**：32サービスを全部申請する前に、実際に送客されている候補を`report:revenue`で抽出する。承認待ちの案件を「すぐ利益が出る手段」とは扱わない。
4. **実績のある入口を優先**：Search Consoleから同期間のページ・クエリ別の検索クリックを確認。流入のあるページと読者の目的を先に改善。インデックス確認前の新記事量産やドメイン変更だけで即増収を期待しない。
5. **同期間の精算と実費を集計**：確定報酬−運営費がプラスかを確認。クリックの増加、未確定成果、確定利益を分ける。

## 実績から次の作業を決める表

| 観測する実績 | 次の作業 |
| --- | --- |
| 検索表示があるがクリックされない | 実クエリとタイトル・説明・記事の内容を照合。未確認の「最安」「最高」を追加しない |
| 閲覧はあるが比較・予約先への操作がない | ファーストビュー、読者の条件、今回の短い導線とイベント欠損を確認 |
| 通常リンクへ送っている | 該当サービスに適した承認済み素材を接続。利益の取り逃し額は推計しない |
| ASPクリックはあるが確定成果がない | 確定待ち期間、否認、対象外条件、掲載媒体、読者との適合を確認 |
| 確定報酬があるが赤字 | 実際のホスティング・API・外注・広告費の内訳から削減。費用データ未提供時は節約額を断定しない |

記事、診断、ショップクリックはいずれも匿名の操作回数です。人単位の離脱率や成約率ではありません。APIの接続が直っても、ASPの有効性・成果・入金は別の確認です。

## 0円でできることと、今回行っていないこと

コードの改善、既存リンクの正常化、既存記事の内部導線改善、Search Consoleの確認、無料枠でのホスティング検討は追加の有料契約なしで進められます。公開IDの存在だけを根拠に新しい提携を捏造することはできません。

有料広告、自己クリック、無断の大量投稿、新規有料サービスへの契約は行っていません。ホスティングの無料化と独自ドメインの具体策は[無料ドメイン統合の手順](VIVLICA-FREE-DOMAIN.md)に分けています。
