# Vivlica.comへの統合・収益運用

この変更は `https://vivlica.com` のルートに既存の比較サイトを統合する構成です。
既存のVercel/GitHub連携（ka1tetsus-projects / hikaku-labo）を確認し、PR #15をマージして `https://hikaku-labo.vercel.app` に本番デプロイしました。DNS・Vivlica.comのプロジェクトへの紐付け・ASP管理画面への操作は未実施です。
このクラウド環境からのVivlica.comへのHTTP接続は、プロキシに403で拒否されました。
既存サイトの有無やDNSの状態が確認できていないため、既存サイトがある場合は内容を保全してから公開してください。
既存Vivlicaのサブパスへの統合を行う場合は、公開前にルーティング・アセットURL・canonicalの構成を別途調整してください。

## 実装した改善

- Vivlicaブランド、canonical、OGP画像9種類、構造化データ、robots・サイトマップを統一。
- 全60ページを事前描画。36件のSIMペア比較、10地域の回線比較、方針ページ3件を含む。
- 現在のスマホ代・データ量・相談方法・同条件の回線数・初期費用から年間差額を試算。
- 比較への移動時に使い方を引き継ぐ。金額をURLやログに含めない。
- 差額がマイナスの場合も支出増として表示。安くならない人に節約を約束しない。
- 商品APIが取得できない場合も、PRを明示した既存のモール検索リンクと再試行導線を表示。
- 通信とITの紹介リンク設定を `VITE_AFF_URL_<ID>` で共通化。
- ページ・広告配置ごとのクリックと、診断完了→比較移動の操作を集計。
- `vercel.json` で旧Vercelドメインとwwwドメインから正規ドメインへ恒久リダイレクト。パスを維持。

## 公開の手順

1. 対象のVercelプロジェクトを確認し、既存サイトがあればバックアップとURLの対応を確認する。
2. Vercel Domainsに `vivlica.com` と `www.vivlica.com` を追加し、画面が指定するDNSレコードを設定する。レコード値を推測して設定しない。
3. ビルドは `npm run build`、出力は `dist`。`SITE_ORIGIN=https://vivlica.com` と `SITE_URL=https://vivlica.com` を設定する（コード既定値も同じ）。
4. 楽天APIの許可サイト・各ASPの媒体登録をVivlica.comに更新する。既存の商品アフィリエイトIDの所有・有効性をASPで確認する。
5. 楽天の検索を使う場合は環境設定に `RAKUTEN_ACCESS_KEY` を安全に設定する。Yahoo!自動比較には `YAHOO_SHOPPING_CLIENT_ID` が必要。チャットやリポジトリにキーを保存しない。
6. Yahoo!トラベルのA8素材は原文を保持している。旧ドメインでの登録確認を新ドメインの承認とみなさない。新媒体URLと掲載条件を確認後、`VITE_A8_TRAVEL_REGISTERED_ORIGIN=https://vivlica.com` を設定して再ビルドする。それまでは通常の公式リンクとして案内する。
7. `npm run test:all`、`npm run lint`、`npm run build`、`npm run verify:build`、`npm run audit:affiliate` を実行する。
8. デプロイ後、正規ドメインで主要ページ・商品検索・`/api/track` の応答を確認する。旧ドメインとwwwからパス・クエリが維持され、ループなく正規ドメインへ移動することを確認する。ローカルのビルド検証だけではDNS・TLS・Vercelリダイレクト・外部API接続の成功は確認できない。
9. Search Consoleに新ドメインを登録してサイトマップを送信し、必要に応じて旧プロパティからアドレス変更を行う。

## 報酬につながるリンクを増やす

通信・ITの広告設定は監査時点で0件です。新しい提携や報酬額はコードでは作れません。
比較結果と読者の目的が合うサービスについて提携し、承認済みの公開計測URLをVercelのビルド環境変数に設定してください。

```sh
npm run audit:affiliate
```

全サービスのID、設定すべき環境変数名、紹介リンクか通常の公式リンクかを出力します。
URLや認証情報は出力しません。URLの存在だけでは媒体承認・報酬発生は証明できません。
設定例の変数名は `VITE_AFF_URL_IIJMIO`、`VITE_AFF_URL_AHAMO`、`VITE_AFF_URL_DOCOMO_HIKARI`、`VITE_AFF_URL_XSERVER_WP`。
実際のURLは各ASPから取得してください。A8が原文HTMLの掲載を求める素材は、リンクだけを抽出せず `src/tools/a8Placements.js` へ原文を保存します。
通常の公式リンクも残し、広告報酬で比較順位を変更しません。

## 集計して改善する

Vercelの関数ログから必要な期間のJSON/NDJSONを安全な場所に書き出し、次のコマンドで集計します。
ログ書き出し機能の可否と保存期間は利用プランに依存します。この実装は永続DBではありません。

```sh
npm run report:revenue -- /tmp/vivlica-logs.ndjson \
  --from 2026-10-01T00:00:00+09:00 --to 2026-11-01T00:00:00+09:00
```

開始日時を含み、終了日時を含まない期間です。`page`別の閲覧数、外部クリック数、PRクリック数、診断完了数、比較移動数と、サービス・配置別のクリックを出力します。
古いログでページ情報がないクリックは別枠にし、推測で特定ページへ配分しません。
`outboundClicksPer100Views` は100閲覧あたりの操作回数で、利用者の割合ではありません。繰り返しクリックにより100を超える場合があります。
分母となる閲覧がない場合は `null`。ボット・ログ欠損の影響があり、売上・人数・成約数の代わりにはなりません。

利益を出す場合だけ、同じ期間についてASPの確定報酬と実費をまとめたJSONを別途用意します。
以下は書式です。金額は所有者が実際の精算額・請求額で置き換えてください。

```json
{
  "from": "2026-10-01T00:00:00+09:00",
  "to": "2026-11-01T00:00:00+09:00",
  "confirmedCommission": 0,
  "operatingCosts": 0
}
```

```sh
npm run report:revenue -- /tmp/vivlica-logs.ndjson \
  --from 2026-10-01T00:00:00+09:00 --to 2026-11-01T00:00:00+09:00 \
  --finance /tmp/vivlica-settlements.json
```

期間の一致を必須とし、利益は入力した確定報酬−運営費から算出します。金額の正しさを独立確認する機能ではありません。金額未提供時は利益不明として `financials: null` を返します。

週ごとに、検索流入→閲覧→診断完了→比較移動→サービス別送客→ASP確定報酬を同期間で見てください。
診断完了から比較移動が少なければ結果の説明・選択肢を改善し、送客があっても成果がなければ案件と読者条件の適合を確認します。
利益の検証前に広告費や有料API利用を増やさないことを推奨します。

## 有料AIのコストを守る

`/api/article` と `/api/reviewSummary` は管理者用です。ブラウザの診断やコンシェルジュには使いません。
`OPENAI_API_KEY` だけを設定しても外部から有料生成できないよう、`AI_GENERATION_TOKEN` によるBearer認証を必須にしました。
両方の値を安全に設定した場合だけ利用でき、未設定時は503、認証不一致時は401を返します。
レビュー件数・文字数、出力トークン数、応答待ち時間も制限します。ダミーのレビュー要約は返しません。
`AI_GENERATION_TOKEN` を `VITE_` 変数や公開リンクに入れないでください。
管理用の記事生成スクリプトもこのBearer認証を送信します。API側の上限は月間の費用上限ではないため、プロバイダー側の予算設定も併用してください。
生成物は編集用下書きで、公開前の事実確認が必要です。

## 追加の成約導線と費用削減

- 固定費診断で初年度の支出が下がる試算になったとき、候補の公式サイトへ直接進めるリンクを表示します。承認済み成果URLが設定されていればPRとして案内します。比較一覧への移動も残します。
- SIM・光回線・カード・IT比較では、最初の候補を通り過ぎたスマートフォン画面に確認ボタンを表示します。条件を変更すると候補とリンクも更新します。報酬額での並べ替えはしません。
- IT比較の最初の候補にも予算・年払い・手数料の注意を表示します。無料予算に合わない候補を「無料」として案内しません。
- トップでは入力のない汎用商品検索を実行しません。商品検索の入力・カテゴリ選択・検索URLからのアクセスでAPIを呼び出します。
- 古い検索は中断し、新しい結果を上書きしないようにします。検索の応答待ちと本文読み取りに上限を設けました。
- 楽天APIの再試行はアフィリエイト設定に関する400/403エラーに限定します。レート制限や障害で同じ呼び出しを繰り返しません。Yahooを含め、両価格ソースを取得できなかった応答はCDNにキャッシュしません。

### 広告設定をまとめる

複数サービスの承認済み公開計測URLを `VITE_AFFILIATE_LINKS` のJSONにまとめて設定できます。
サービスIDは `npm run audit:affiliate` に出力します。値はASPから取得した実URLに置き換えてください。APIキーなどの秘密値をこの公開変数に入れないでください。
個別の `VITE_AFF_URL_<ID>` に有効な文字列が指定されていればそちらを優先します。

壊れたJSON、未知のサービスID、HTTPSでないURL、許可されたASP以外のURLは広告として有効化しません。
監査で `invalid_bundle` や `invalid-link-official-fallback` が出た場合は設定を直してください。
原文HTML掲載が必要なA8素材は、従来どおりHTMLのまま設定し、JSONへリンクだけを抽出しません。

### 次に改善する箇所を絞る

`npm run report:revenue` に `merchants` と `nextActions` を追加しました。

- 通常リンクの送客が記録された通信・ITサービスは、提携可否と成果リンク設定の確認候補に出します。
- 診断完了後、比較一覧や診断結果から公式への移動が記録されなければ、結果画面・計測を確認する候補に出します。
- 所有者が入力した同期間の確定報酬を運営費が上回れば、費用内訳の確認を促します。

推定報酬・架空のEPC・利用者単位の離脱率は算出しません。送客があることだけでは成果の発生や提携可能性を確認できないため、ASPの実データと合わせて判断してください。
